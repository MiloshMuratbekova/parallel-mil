# Assignment 3: Архитектура GPU и оптимизация CUDA-программ

## Описание заданий

### Задание 1 (25 баллов): Глобальная vs Разделяемая память
Реализация программы для поэлементной обработки массива с двумя версиями:
- С использованием только глобальной памяти
- С использованием разделяемой памяти

Сравнение производительности для массива из 1,000,000 элементов.

**Файлы:** `task_1/main.cu`, `task_1/Makefile`

### Задание 2 (25 баллов): Влияние размера блока
Исследование влияния размера блока потоков на производительность программы сложения двух массивов.

Тестирование размеров блока: 32, 64, 128, 256, 512, 1024 потоков.

**Файлы:** `task_2/main.cu`, `task_2/Makefile`

### Задание 3 (25 баллов): Коалесцированный доступ к памяти
Демонстрация коалесцированного и некоалесцированного доступа к глобальной памяти:
- Последовательный доступ (коалесцированный)
- Доступ со смещением (некоалесцированный)
- Обратный порядок доступа (некоалесцированный)

**Файлы:** `task_3/main.cu`, `task_3/Makefile`

### Задание 4 (25 баллов): Оптимизация конфигурации
Подбор оптимальных параметров конфигурации сетки и блоков потоков. Сравнение различных конфигураций:
- Неоптимальные (маленькие блоки, большие блоки, некратные warp size)
- Оптимальные (стандартные размеры, с учетом occupancy)

**Файлы:** `task_4/main.cu`, `task_4/Makefile`

## Компиляция и запуск

### Требования
- NVIDIA GPU с поддержкой CUDA
- CUDA Toolkit (nvcc компилятор)
- Make

### Компиляция отдельного задания
```bash
cd task_X  # где X = 1, 2, 3, или 4
make       # компиляция
make run   # запуск
make clean # очистка
```

### Запуск всех заданий
```bash
# Из корневой директории assignment_3
for i in {1..4}; do
    echo "=== Running Task $i ==="
    cd task_$i
    make run
    cd ..
    echo ""
done
```

## Ожидаемые результаты

### Task 1: Разделяемая память
- Разделяемая память может быть быстрее или медленнее в зависимости от алгоритма
- Для простого умножения на константу накладные расходы могут превысить выигрыш

### Task 2: Размер блока
- Оптимальный размер: обычно 256-512 потоков
- Слишком маленькие блоки (<64): низкая производительность
- Слишком большие (>512): ограничение occupancy

### Task 3: Коалесценция
- Коалесцированный доступ в 2-10 раз быстрее
- Некоалесцированный доступ значительно снижает пропускную способность

### Task 4: Оптимизация
- Правильная конфигурация дает ускорение в 2-5 раз
- Важно учитывать: размер варпа, число SM, occupancy

## Примечания
- Результаты могут отличаться в зависимости от GPU
- Для получения стабильных результатов программы выполняют несколько прогревочных запусков
- Используется CUDA Events API для точного измерения времени
